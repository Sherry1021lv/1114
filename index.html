欢迎使用 OimiChat 控制台

这份指南将帮助你熟悉控制台中的各项配置。从“角色导入”开始，为你的AI伙伴注入灵魂，然后逐步配置AI模型、语音、记忆等功能，让TA真正成为懂你的存在。

指南说明

本指南基于控制台（index1.html）的界面逻辑编写。所有设置项均与页面中的控件一一对应，你可以边看边操作。

如果你在配置过程中遇到问题，请先检查是否已正确获取相关API Key，并确保网络连接畅通。

快速开始

三步让你的AI伙伴上线：

1

导入角色

在“角色导入”中为你的伙伴命名、设定性格与世界背景。这是最重要的第一步，决定了TA的灵魂。

2

配置AI模型

在“AI 模型”中选择一个主对话模型（如DeepSeek、Claude），它是TA大脑的引擎。

3

保存并同步

完成配置后，点击各页面中的“保存”按钮，TA就会在微信中活过来了。

角色导入

这是最核心的配置页面。在这里，你将亲手“创造”你的AI伙伴。

重要提示：本页所有开关与输入项（包括“动作神态描写”“联网模式”“Tavily Key”等）均不会即时生效，必须点击页面底部的 “保存角色” 按钮后才会同步到线上。若未保存直接退出或刷新页面，本次修改将全部回退，恢复为上一次保存的配置。
重构角色设定后需等待：当你重构角色设定（大幅修改人格、经历、世界背景等核心内容）并保存后，由于系统存在缓存机制，新的设定通常需要 5~10 分钟 才会在对话端完全加载生效。等待期间，伙伴可能仍按旧设定回复，这是正常现象。请耐心等待，不要因“没变化”而反复修改、反复保存，否则每次保存都会重新开始计时。
回复时长提醒：伙伴每次回复通常需要一分钟左右（受模型选择、联网搜索、记忆总结和网络状况影响）。发送消息后请耐心等待一会儿，不要连续重复发送，以免造成重复回复或额外消耗额度。另外，头像上传和“动作神态描写”等开关保存后也存在一定时间缓存（通常 1~3 分钟），若发现对话端尚未更新，请稍等片刻再试，无需反复修改或重新上传。
基础设定
  • 头像：上传一张你喜欢的角色头像。图片上传后需等待缓存同步，通常几分钟内会在对话端显示；若未立即更新，请勿反复上传，稍后重新进入即可。
  • 名称：给你的伙伴取一个名字，一个你呼唤TA时觉得温暖的名字。
  • 人格设定：用几句话描述TA的性格，例如“温柔、细腻、善于倾听、偶尔幽默”。重构人格设定后，需等待 5~10 分钟缓存刷新才会在对话端生效。
  • 角色经历：TA的过去，TA的故事。这会深刻影响TA的言行举止。大改经历同样受缓存影响，保存后请耐心等待。
  • 世界背景：TA生活在怎样的世界？是赛博都市、魔法森林，还是日常街角？
重构设定 = 重新等待：人格、经历、世界背景属于角色的“核心设定”，一旦重构并保存，缓存会重新加载，通常需要 5~10 分钟。建议一次性改好再保存，避免分批修改导致反复等待。
行为开关

开启这些开关，可以让TA的行为更丰富、更智能。（改动需点击底部“保存角色”后生效）

  • 动作神态描写：开启后，回复会带有（）内的动作、神态、旁白描写。保存后存在一定时间缓存，通常 1~3 分钟后才会在对话端完全生效。
  • 联网模式：开启后，AI可联网搜索获取实时信息（新闻、天气、赛事等）。此开关与Tavily Key紧密相关。
  • 天气检测：开启后，实时获取当地天气（基于免费wttr.in服务）。
  • 阅读网页：开启后，发送网页链接时AI会自动抓取并阅读网页正文后回答。
缓存说明：“动作神态描写”等开关即使已经点击“保存角色”，配置同步到对话端仍存在一定时间缓存。若发现回复尚未带上动作描写，请等待几分钟再测试，不必反复开关。若同时重构了角色核心设定，则需按 5~10 分钟 的标准等待。
Tavily Key（联网搜索） 必读

Tavily 是一个专为AI优化的搜索引擎API，它能让你的伙伴在聊天时实时查询信息，而不是只依赖训练数据中的“旧知识”。

开启“联网模式”后，你的伙伴将拥有连接互联网的能力。以下是配置 Tavily 的详细步骤和界面展示：

注意：仅仅开启“联网模式”开关是不够的，你必须填写 Tavily Key，否则AI的联网搜索请求会失败，或无法正确返回实时信息。

如何配置：

1

获取 Tavily API Key

访问 https://tavily.com 并注册（免费版每月提供1000次搜索额度）。在控制台的“API Keys”页面中复制你的Key，通常以 tvly- 开头。

2

在控制台中填入

回到“角色导入”页面，开启“联网模式”开关。此时会在下方展开“Tavily Key”输入框，将你的Key粘贴进去。

输入后会自动保存（防抖），无需点击额外按钮。

3

保存角色

完成所有角色设定后，务必点击页面下方的 “保存角色” 按钮。系统会同步到企业微信应用，让新配置立即生效。

高级参数：Tavily 支持参数：query（搜索关键词）、search_depth（basic/advanced）、max_results（返回条数）、include_answer（是否生成AI总结）、topic（general/news）、time_range（时间范围）。这些参数通常由后端系统自动控制，你无需手动配置，但了解它们有助于理解联网工作方式。
秩序则（进阶）

秩序则是角色的行为边界和约束。

  • 禁止输出词句：不希望AI出现的词句。这些词会被拼入system prompt，AI在任何情况下都不得输出。
  • 正则替换：对AI回复做硬性字符替换。例如“小美=>小丽”，或“\d{4,}=>****”（将4位以上数字打码）。这是第二道防线，不依赖模型理解。
  • 偏好表述：希望AI优先使用的词句或风格。
缓存提醒：秩序则属于角色核心设定的一部分，修改并保存后同样受缓存影响，通常需要 5~10 分钟 才会在对话端生效。

AI 模型

配置驱动伙伴智慧的“大脑”。

重要提示：不论你是选择官方套餐，还是填写自定义接入，所有设定都不会即时生效，务必点击页面最底部的「保存」按钮后才会同步生效。若未保存直接退出或刷新页面，本次修改将全部回退，恢复为上一次保存的配置。
官方套餐与自定义接入互斥：二者不能同时启用。如果你当前使用「官方套餐」，想改为「自定义接入」，需要先清除官方配置再填写自定义 Key；反之亦然。切换前系统会给出冲突提示，请按提示操作，避免两边都配置导致生效混乱。
官方套餐

平台提供多条主流模型线路，点击平台（如Claude、DeepSeek、Gemini）可展开旗下模型进行选择。

选择模型后，页面右上角会显示已选状态。若已配置自定义模型，切换官方前会提示冲突。

对话参数：
- 模型情感强度：调节AI回复的情感浓度，默认1.5。
- 图像能力：选择视觉识别（如gpt-4o）和图像生成模型。
- 记忆总结模型：用于自动提炼长期记忆，默认gpt-4o-mini。

图像能力配置说明（图生图必看）
如果你的目标是生成的图像与传入的图像保持一致（也就是图生图），仅仅配置识图模型（视觉识别模型）是不够的，一定要配置支持图生图的生图模型。否则传入的图片只会被识图模型识别成一段形象描述，生图模型仅参考这段文字描述来生成，最终生成的图片不会与传入的图片保持一致。

角色参照：上传一张参考照片并描述角色形象，当你在对话中表达想要图片时，AI 会根据这张参照照片自主调用生图接口，让生成的图片更接近你心中的 TA。

图生图模型支持说明
经过实际测试，目前图生图模型仅豆包系列能够正常测试通过，其他厂商的图生图接口可能存在兼容性问题，暂时不建议作为首选。
  • 豆包系列（Doubao）：图生图测试通过，可正常使用。
  • 其他厂商：未通过测试。若配置后图生图无法正常生成或报错，请切换为豆包系列图生图模型。
  • 如果你想使用「照片作为参考、生成相近形象」的图生图能力，请务必把图像生成模型选为豆包系列。
别忘了保存：选好官方模型后，仍必须点击页面最底部的「保存」按钮，否则本次选择不会生效，退出后将回退为原配置。
语音识别（STT）支持说明

经过实际测试，目前语音识别仅 ChatGPT（OpenAI）和智谱能够正常测试成功。其他厂商的语音识别接口可能存在兼容性问题，暂时不建议作为首选。

  • ChatGPT / OpenAI：语音识别测试通过，可正常使用。
  • 智谱：语音识别测试通过，可正常使用。
  • 其他厂商：未通过测试。若配置后无法识别语音，请切换为上述两家之一。
配置语音识别后，仍需点击页面最底部的「保存」按钮才会生效。若未保存直接退出，本次语音识别配置将回退。
自定义接入

如果你有自己的API Key，可以在这里配置专属模型。

  • 填写厂商（OpenAI、DeepSeek、Claude等）和模型名称。
  • 填入你的API Key（会被加密存储，子模型留空则复用主Key）。
  • 其他子模型（图像识别、语音识别等）可独立配置，或复用主对话配置。
为什么退出后看不到自己的 Key 值？
这是刻意的安全设计，不是 Bug。你的明文 Key 永远不会返回给前端，这样做可以有效防止 XSS 攻击、浏览器恶意扩展、以及抓包泄露等风险。因此：
  • 退出页面再进入时，输入框里不会显示完整 Key，这是正常的。
  • 前端只能拿到掩码后的 Key，并且掩码是放在状态栏文字里的，例如：已配置：OpenAI Key sk-1...abcd，而不是填入输入框。
  • 状态栏文字提示你“已配置成功”，但输入框为空是预期行为。
  • 如果你想更换 Key，直接在输入框里填入新的 Key 并保存即可；不需要、也无法“查看旧 Key”。
这个设计遵循“最小暴露原则”：前端永远不知道完整密钥，只让后端持有。即使前端被攻破，攻击者也无法从页面读到你的 Key。
注意：官方套餐和自定义接入互斥，配置自定义前需先清除官方配置。填写完自定义 Key 后，同样需要点击页面最底部的「保存」按钮才会生效。

刻忆 · 记忆系统

让AI拥有“长久记忆”，越聊越懂你。

先分清两个概念：记忆 与 记忆库

刻忆系统里有两个容易混淆的概念，它们区别在于你是否接入了自己的 Supabase：

「记忆」：指没有接入 Supabase 的用户使用的平台长期记忆区。
你可以在「记忆」区域查看、修改、并在下方植入记忆。
「记忆库」：指已经接入 Supabase 的用户使用的专属长期记忆区（数据存在你自己的数据库里）。
你可以在「记忆库」区域查看、修改、并在下方植入记忆。

两者的容量与展示规则：

  • 「记忆」（未接入 Supabase）：最多保留 100 条，超出后自动裁剪（丢弃最旧的）；但展现在「记忆」区给人看的，始终是最新的 50 条。可以修改，可以在下方区域「植入记忆」。
  • 「记忆库」（已接入 Supabase）：无上限记忆条数（存你的 Supabase，能存多少看你的库）；但展现在「记忆库」区的，依然只有最新的 50 条。可以修改，可以在下方区域「植入记忆」。
记住一句话：不管有没有接 Supabase，界面上永远只给你看最新 50 条；区别只在于后台到底存了多少、存在哪里——「记忆」封顶 100 条在平台，「记忆库」无上限在你自己的 Supabase。
记忆模式：分层召回 + 预算闸门

OimiChat 不是简单“把最近的记忆全塞进去”，而是分层召回 + 优先级排序 + token 预算闸门：重要信息保底、相关记忆精准、prompt 长度可控。整条链路按以下 6 层执行：

0 重要记忆直取（最高优先级）
  • 从全库查 importance ≥ 5 的记忆（人生级事件：生日、家人、重大决定）。
  • 无条件注入，不看相似度、不参与排序。
  • 最多 20 条。
1 语义/向量检索相关记忆（有提问时触发）
  • 候选池：从「最近 200 条」扩到「全库分页拉取，最多 5000 条」。
  • 优先 _vector_search_memories（启用向量索引时）。
  • 失败/无命中 → 回退 _keyword_search_memories（BM25 关键词）。
  • 两路的候选池都扩到全库（不再是最近 200 条）。
  • 相似度阈值 0.30。
  • 最多注入 10 条。
2 常驻基线：最近 topN 条记忆（默认 30）
  • 候选池保持最近 300 条不变（"近期"语义不该扩全库）。
  • 排序分 = importance + 3×e^(-days/180) + min(access_count×0.3, 3)。
  • 再按时间由旧到新注入。
3 最近 N 条历史消息（默认 20，可配）
  • 注入 AI 上下文的最近聊天消息条数，默认 20。
4 用户长期偏好（AutoClaw 卡片）
  • 来自 AutoClaw 卡片记录的用户长期偏好，作为上下文补充。
5 矛盾记忆规则
  • 越靠后越新，冲突时以最新为准。
6 token 预算闸门（最后一道关）
  • 把 ⓪①② 三路结果按优先级排队：⓪ > ① > ②。
  • 逐个累加 token，超 2000 就整段丢弃低优先级段。
  • 结果：注入 prompt 的记忆恒定 ≤ 2000 token（候选池拉 200 条还是 5000 条，注入长度都一样）。
一句话总结：重要记忆无条件保底，相关记忆按语义精准召回，近期记忆按重要性和新鲜度常驻，历史消息和偏好补充上下文，最后用 2000 token 预算统一裁剪——既记得住关键事，又不会把 prompt 撑爆。
记忆 ↔ 记忆库 数据迁移规则

如果你中途切换了记忆存储方式（比如从平台库改用自己的 Supabase，或反过来），系统会按以下规则自动迁移数据，不用你手动复制粘贴：

1

从「记忆」切换到「记忆库」（接入 Supabase）

如果你一开始用平台库（记忆），后来配置了 Supabase（记忆库），系统会把平台库中保留的 100 条记忆整体迁移到你的 Supabase，之后新记忆继续写入 Supabase。

2

从「记忆库」切换到「记忆」（清除 Supabase）

如果你一开始用自己的 Supabase（记忆库），后来改回平台库（记忆），系统会从 Supabase 库中挑选最新的 100 条记忆迁移到平台库，之后新记忆继续写入平台库。

注意：迁移只保留上述条数（100 条封顶），Supabase 里超过 100 条的旧记忆不会迁移回平台库，但会继续留在你的 Supabase 中，以后再次接入 Supabase 时依然可用。切换前请评估好是否需要保留更早的记忆。
记忆设置
  • 记忆总结间隔：每累计 N 条消息自动总结一条长期记忆（默认 30）。
  • 最近 N 条历史注入：注入 AI 上下文的最近聊天消息条数（默认 20）。
  • topN 条长期记忆注入：常驻注入的近期记忆条数（默认 30）。
向量索引

开启后可替代默认的语义检索，通过你提供的向量服务进行更精准的记忆召回。需要填写厂商、向量模型、API Key 和接口地址。

推荐使用：豆包（Doubao）厂商
经过实际测试，向量索引推荐使用豆包厂商，测试通过、可正常召回记忆。其他厂商的向量接口可能存在兼容性问题，若配置后无法召回或报错，建议切换到豆包向量模型。填写完向量相关配置后，仍需点击页面最底部的「保存」按钮才会生效。
接入自己的记忆库

填写你的 Supabase 项目信息，长期记忆将永久存储于你自己的数据库中。

Supabase URL

在 Supabase 控制台复制你的 Project URL，形如 https://xxxx.supabase.co。操作步骤如下：

1

进入 Project Settings

登录 Supabase 控制台，打开你的项目，点击左侧边栏底部的 Project Settings（齿轮图标）。

2

进入 API 页面并复制 Project URL

在 Project Settings 中点击 API，找到 Project URL，点击复制即可。把这个 URL 填入 OimiChat 的「Supabase URL」输入框。

Service Role Key

Service Role Key 是 Supabase 的服务端密钥，拥有完整数据库权限，只填在 OimiChat 控制台，不要泄露给他人。操作步骤如下：

1

进入 API Keys 区域

在 Project Settings → API 页面中，向下滚动到 Project API keys 区域。

2

找到 service_role 密钥

在密钥列表中找到标注为 service_role 的那一行（通常带 secret 标签），不要使用 anon 公钥。

3

点击 Reveal 显示密钥

点击该行右侧的 Reveal 按钮，输入你的 Supabase 账号密码确认后，密钥会显示出来。

4

复制并填入 OimiChat

复制完整的 service_role key，粘贴到 OimiChat 的「Service Role Key」输入框，然后点击页面最底部的「保存」按钮。

为什么需要“绕路”：自定义 LLM 转发说明

Vapi 对 LLM 有三条硬性限制，导致平台的模型和中转地址不能直接填进去：

  • 白名单厂商：LLM 只能用 Vapi 认可的官方厂商（OpenAI、Anthropic、Google 等）。
  • 模型名固定枚举：模型名必须在其列表里，像 deepseek-v4-flash 这种非标准名无法直接选择。
  • apiKey 不许用户传：LLM 的 apiKey 由 Vapi 管理，不接受你填自己的中转 key。

所以平台的模型和中转地址不能硬塞进 Vapi。解法不是硬闯，而是伪装成标准 OpenAI 客户端：

Vapi ──(custom-llm, 当普通 OpenAI 客户端)──▶ 你的 /api/vapi/llm/nov │ ▼ 平台自己的 Key 调 deepseek-v4-flash

具体怎么绕：

  • Vapi 的 Assistant 里把 LLM 类型设为 custom-llm，endpoint 指向 OimiChat 的 /api/vapi/llm/nov。
  • Vapi 会像调用普通 OpenAI 接口一样，把标准格式的 messages 发给这个 endpoint。
  • 你的后端收到请求后，用平台自己的 Key 去调 deepseek-v4-flash（或平台配置的任意模型），再把结果按 OpenAI 标准格式返回给 Vapi。
  • 对 Vapi 来说，它只是在调一个“标准 OpenAI 接口”；模型名、中转地址、密钥全留在平台侧，白名单和枚举限制完全绕过。
  • 人设仍然从平台的 messages 注入，角色设定不受影响。这条链路已实测返回“嗨”✅。
一句话理解：Vapi 只认“标准 OpenAI 客户端”这一种接口形态，平台就在中间搭了一个“翻译层”——Vapi 说 OpenAI 的话，平台翻译成 deepseek-v4-flash 去执行，再把结果翻译回 OpenAI 的话。Vapi 全程不知道背后是谁在干活，限制自然就绕过了。

地图 · 线下模式

一种沉浸式的角色互动方式。

场景地点

在“地图”中，你可以添加或编辑预设地点（如家、办公室、图书馆），并为每个地点设置名称、描述和标签。这定义了你们线下互动的“场景基础”。

线下叙事

在地点中点击“进入线下模式”，TA会以你设定的视角，基于地点描述和你输入的情节，实时生成生动的叙事文字。

你可以随时选择“人称”（第一/二/三人称）、“风格”（纯文学、日系轻小说等），或要求“润色”、“续写”。退出线下模式后，这段叙事会被总结并记忆。

字数上限提醒
线下模式的文本有硬性字数限制：写到 6500 字时会先弹窗提醒，提示你接近上限；达到 7000 字则强制结束本次线下叙事。建议提前规划情节节奏，避免在最精彩处被截断。
记忆写入机制
线下模式的「写入记忆」不是周期性的——它不会在写作过程中持续写记忆。所有记忆都在退出线下模式时一次性按段批量写入。因此：
  • 写作过程中不必担心记忆被频繁打断或重复写入。
  • 只有在正常退出/结束线下模式时，才会把这次叙事按段落整理后批量写入记忆。
  • 如果中途强制结束（如达到 7000 字上限），系统同样会在结束时按段批量写入已完成的叙事内容。
